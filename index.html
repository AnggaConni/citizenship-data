Citizenship Data Explorer

A manually assembled and curated knowledge base for structured citizenship and country-related information. The records are selected and maintained by a human curator rather than automatically harvested as a live global observation feed.

Biodiversity Explorer

An exploratory interface for species occurrence records. Choose a country first—or explicitly select Worldwide—then scan public GBIF records in the background. The app deduplicates the results into one representative point per species; opening a species fetches that taxon’s worldwide records.

How its data is managed
Live API retrieval + in-browser processing

The biodiversity scan runs in the browser and reads public data from source services. It does not copy that occurrence database into the Citizenship Explorer’s private storage. Images and research metadata appear only when the source provides matching records.

  • GBIF species and records
  • Representative map points
  • Available multimedia
  • Related research & datasets

Inside the biodiversity scanner

It scans progressively — it does not freeze and wait.

First choose a country or the explicit Worldwide option and start the scan. The app then uses asynchronous network requests and processes results one page at a time. While the browser waits for a response, the rest of the interface can continue responding to your actions.

What “async” means here: fetching a page from GBIF is an asynchronous operation. The browser can keep handling map zooming and panning, searching for a species, opening a species modal, and reading results while the next page is requested. The scan continues in the background until it finishes, fails on unavailable pages, or you press Stop scan. Public API response times and rate limits can still affect how quickly new data arrives.
01

Request a page

GBIF occurrence search is queried for records with geographic coordinates and without a flagged geospatial issue. Each page requests up to 300 records.

02

Process immediately

Each page is inspected as it arrives. The app counts unique occurrence records, checks for media, and extracts a compact species entry. Full raw pages are not kept in the app’s request cache.

03

Deduplicate by species

Records sharing the same GBIF species key are merged into one entry. If a species appears in many places, the main map still displays one representative point for it.

04

Update the explorer

The map and counters update as pages are processed. The species list and gallery refresh periodically, so you can explore discoveries before the scan has completed.

What happens when you keep browsing?

You do not need to sit and watch the progress bar. The scanner works through network requests in the background; meanwhile, the map and species controls remain usable.

Scope and limits

A useful sample is not the same as a global census.

It is important to understand exactly what is counted, where each point comes from, and what this version does not claim to measure.

Why the scan currently stops at 9,900 records

The current browser scan is deliberately capped at 9,900 occurrence rows per run for the selected country, or for Worldwide if you explicitly choose a global scan. It works through pages of up to 300 records and deduplicates species while processing them.

This is an API-friendly interactive scan limit, not a measurement of the maximum RAM your computer can use. Public GBIF search has pagination and high-offset constraints; for larger or exhaustive extracts, GBIF provides a separate download workflow.

  • Progress is visible, and the scan can be stopped.
  • A page that fails after retries may leave a gap; the status message reports failures where detected.
  • The result is a deduplicated view of up to 9,900 matching occurrence rows from the chosen country or explicit worldwide scan—not every species documented by GBIF.

What does one map point mean?

The point represents one georeferenced occurrence chosen from the scanned records for that species. It is there to make the species discoverable on the map.

  • It does mean: GBIF returned at least one coordinate-bearing record for that species in the scanned pages.
  • It does not mean: the point is the species’ exact range, its only habitat, the centre of its population, or proof that it lives there today.
  • It does not mean: a species not shown on the map is absent from the world. It may simply not appear in the scanned records or may lack usable coordinates.
  • Images are shown only when usable multimedia is attached to retrieved occurrence records; image availability and reuse rights vary.
Source transparency

Which sources power which features?

The tools keep source responsibilities separate. Metadata from one service is not represented as if it came from another.

Two different data models

Curated records versus live public observations.

Neither method replaces the other. Manual curation supports intentional selection and context; open data APIs support broad discovery and source-linked exploration.

Common questions

Avoiding common misunderstandings.

Does the biodiversity scan download all of GBIF?

No. After you select a country—or explicitly choose Worldwide—it scans up to 9,900 matching coordinate-bearing occurrence rows per run, then deduplicates by species key. GBIF's full catalogue contains far more data. Large or exhaustive extracts should use GBIF's download services and appropriate processing infrastructure.

Can I use the map while the scan is running?

Yes. Requests are asynchronous and each result page is processed as it arrives. Map interaction, the search field, species list, gallery, and detail modal remain usable. Network congestion or API rate limits can still make requests slower.

Why can the same species have many global records but just one main-map point?

The main map is designed to explore unique species, not render every occurrence. Clicking the species then opens a separate global-record view where the app loads occurrence records in smaller pages and maps the loaded coordinate-bearing records.

Are all species shown with photos?

No. Images are obtained from multimedia fields attached to occurrence records. Some species have no attached images, some image URLs may no longer work, and licences or attribution requirements vary by image.

Does the Citizenship Explorer use the GBIF database?

No. It is a separate, manually curated project using its own project-managed storage endpoint. The biodiversity scanner does not write its results into the citizenship data store.

Is this an official UNESCO or GBIF product?

No. Open Data Explorers is an independent project. It uses source APIs and map data from the providers named here; it is not an official UNESCO, GBIF, OpenAlex, Crossref, or OpenStreetMap application.
